# ③ 从芯片测试往哪走：AI4Test 方向路线（2026–2027）

> 传统芯片测试（功能 / 可靠性 / 固件 / Log）+ AI 与大模型，交叉出一个竞争少、门槛实、和我的经历无缝衔接的方向：
> **AI4Test —— 用统计学习与 LLM 做测试数据分析、异常检测与故障归因。**

## 1. 为什么是这个方向

1. **经历可复用**：我已经有真实 UWB 测试流程经验（固件、Log、上位机、可靠性），差的只是把"人肉看 Log"升级为算法；
2. **避开纯算法红海**：不用和 985 论文选手硬拼大模型预训练，而是在懂硬件测试的人里最懂 AI、在懂 AI 的人里最懂测试；
3. **产业真实在投钱**：先进封装、车规芯片、RDA/可靠性分析都在做测试智能化（ATE 数据分析、良率管理 YMS、FDC 故障检测分类）；
4. **8GB 显卡足够**：日志数据小，统计法 / 树模型 / 小自编码器 / 本地小 LLM 全能在笔记本跑；
5. **作品集可脱敏**：所有方法都能在公开日志数据集（Loghub HDFS/BGL）和虚构数据上复现，不依赖雇主私有数据。

## 2. 能力地图（三层）

```
第 0 层（已完成）：测试工程
  UWB 协议与测距原理、功能/可靠性测试、固件版本管理、Log 解析与报告自动化
        │
第 1 层（本仓库进行中）：统计与机器学习分析
  规则告警 → 3σ/MAD 稳健异常检测 → 时序基线 → IsolationForest/LOF
        │
第 2 层（下一步）：日志智能
  Drain 日志模板挖掘 → 模板序列异常 → 失败码聚类 → 良率/通过率的批次分析
        │
第 3 层（差异化）：LLM for Test
  结构化告警 + 日志片段喂给本地/API 小模型 → 自动归因摘要、测试报告草稿、ChatOps
```

## 3. 四个可做的具体项目（按难度递进）

### P1 指标稳健异常检测（已落地 ✅）
- 工具：`scripts/metric_anomaly.py`（3σ + MAD，纯标准库，11 个测试）；
- 学会：为什么 MAD 比 3σ 抗污染、误报率与阈值 k 的关系；
- 下一步：加 EWMA 指数加权（捕捉缓慢漂移，如固件升级后误差基线逐日偏移）。

### P2 日志模板挖掘（Drain）—— 4 周
- **问题**：原始 Log 是半结构化文本，每条都不同（时间戳、ID 不同），无法直接统计；
- **做法**：实现/使用 Drain 算法把 Log 解析成模板（`"DUT=<*> FW=<*> RESULT=FAIL err_code=<*>"`），统计模板频次突增；
- **数据**：先用本仓库虚构日志，再接公开 [Loghub](https://github.com/logpai/loghub) 的 HDFS/BGL（数百万行，真实失败标注）；
- **交付**：模板表 + 频次时间序列 + 异常模板告警 + 单元测试；
- **可讲的面试点**：日志解析的前缀树、相似度阈值、在线/离线解析区别。

### P3 测试失败自动归因（小 ML + 规则）—— 4 周
- **问题**：FAIL 的根因是信号弱（RSSI 低）、超时、CRC、还是固件版本？
- **做法**：
  1. 特征工程：每条/每批次 FAIL 关联 RSSI、err_code、FW 版本、距离档位、时间、治具号；
  2. 无监督：IsolationForest 找异常批次；有标注后：逻辑回归 / 梯度提升做根因分类；
  3. 输出"根因候选 + 证据字段"，而不是黑盒标签；
- **交付**：一个 `root_cause.py`，输入聚合 JSON，输出归因报告；基线对比（规则 vs ML）。

### P4 LLM 测试报告助手（Agent 落地）—— 3–4 周
- **问题**：测试工程师每天要写大量"现象-结论"报告；
- **做法（本地可跑，数据不出本机）**：
  1. 解析 + 异常检测结果组织成结构化 JSON（本仓库已有）；
  2. 用 0.5B–4B 本地模型（Qwen3 小杯）或 API，把 JSON + 相关日志片段转成"测试结论草稿"；
  3. **关键设计：LLM 不接触原始判定，所有数字来自确定性脚本，模型只负责措辞**——可溯源、防幻觉；
  4. 做一个简单评测：数字正确率、引用命中率（呼应 RAGAS 思路）；
- **差异化**：这是"LLM + 硬件测试"，市面作品极少，且工程严谨性是亮点。

## 4. 学习资源与时间表

| 阶段 | 时间（建议） | 学什么 | 对应产出 |
|---|---|---|---|
| 现在–12 月底 | P1 收尾 + EWMA | 稳健统计、统计过程控制 SPC（控制图、Cpk） | metric_anomaly 完善 |
| 1 月（寒假） | P2 Drain + Loghub | 日志解析、时序、pandas 大文件 | 模板挖掘工具 |
| 2 月 | P3 归因 | sklearn、特征工程、可解释性 | root_cause 报告 |
| 寒假实习后 | P4 LLM 助手 | 本地推理、prompt、输出校验、RAG 评测 | demo + 技术文章 |

SPC 补课关键词：控制图（Shewhart / EWMA / CUSUM）、Cpk/Ppk、GR&R（测量系统分析）——这些是半导体制造质量的通用语言，面试时说出来立刻显得"懂行"。

## 5. 和求职岗位的对应说法

- 投 **AI 应用 / Agent 岗**：强调 P4（LLM 处理真实业务数据 + 可溯源工程）；
- 投 **AIOps / 智能运维岗**：强调 P2/P3（日志模板、异常检测、根因），补 Loghub 结果；
- 投 **芯片公司测试 / 良率岗**：强调 UWB 领域知识 + SPC + P1/P3，说"我能把测试数据分析自动化"；
- 投 **大模型评测岗**：强调本仓库和 llm-inference-efficiency-notes 共用的实验纪律（配对、σ、门控、防污染）。

## 6. 红线

- 任何公开作品只用虚构数据与公开数据集，真实产品 Log、客户名、良率数字绝不入库；
- LLM 项目坚持"数字来自确定性代码、模型只做表达"，杜绝模型编造测试结论。
